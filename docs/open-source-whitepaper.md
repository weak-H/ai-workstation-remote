# AI Workstation Remote 开源项目白皮书

> 版本：0.1  
> 日期：2026-10-20  
> 项目定位：面向程序员的、本地优先且厂商中立的 AI 编程 Agent 移动控制层

## 摘要

AI 编程工具正在从一次性问答变成长时间运行的工程任务。开发者会同时使用 Codex、Cursor、Claude Code，以及公司内部的模型网关、OpenRouter、LiteLLM 或其他兼容 API。代码、依赖、终端和凭证仍然在工作站上，但开发者需要在离开电脑后查看进度、补充指令、处理审批或停止错误任务。

官方手机端已经证明了这种需求，但通常将移动端、桌面端、账号、订阅和 Agent runtime 绑定在同一厂商体系中。对使用统一 Router API key、企业模型网关、多种 Agent，或者不希望为远程控制改变模型供应链的开发者而言，这个绑定形成了实际门槛。

AI Workstation Remote 的目标不是再造一个编码 Agent，也不是把完整桌面搬到手机上。它在手机与开发工作站之间提供一层窄而明确的控制协议：

> **手机配对的是用户自己的工作站和任务，而不是某个模型厂商账号；模型凭证保留在工作站，Agent 继续使用原有配置执行。**

当前仓库已经实现 macOS Companion、移动优先 PWA、开发用中继、统一任务协议，以及 Codex、Cursor、Claude Code 三类适配器的首个垂直切片。项目下一阶段的重点不是增加更多 Agent，而是完成持久事件账本、设备密钥、签名命令与端到端加密，使其达到可供个人开发者安全使用的开源版本。

## 1. 要解决的问题

### 1.1 Agent 任务已经超出桌面前台会话

复杂编码任务可能持续数十分钟，并在执行命令、修改文件或访问工具时等待人工确认。开发者离开工位后，任务可能因为一个低风险审批停住，也可能沿错误方向继续消耗时间和额度。

传统远程桌面和手机 SSH 可以进入电脑，但它们暴露的是像素或完整 Shell，而不是 Agent 的结构化状态。用户需要缩放桌面界面、理解终端输出，并承担远程 Shell 带来的宽权限风险。

真正需要远程处理的动作通常只有少数几类：

- 查看 Agent 当前在做什么以及是否完成。
- 阅读对话、命令、文件变更、测试和错误。
- 回答 Agent 的问题或补充纠正指令。
- 对明确范围的一次性动作批准或拒绝。
- 停止失控、错误或不再需要的任务。
- 在指定项目中启动一个新任务。

### 1.2 官方移动控制存在账号边界

官方产品的移动能力首先服务于各自的平台闭环，而不是通用的本地 Agent 控制。

- Codex 官方 Remote connections 要求手机与主机上的 ChatGPT 桌面应用登录同一 ChatGPT 账号和 Workspace，且移动连接不能只从 Codex CLI 或 IDE 扩展建立。连接成功后，执行环境和凭证来自主机。
- Cursor 的 Web/Mobile Agent 以 Cursor 账号、仓库连接和 Cursor 的云任务体系为入口。Cursor 桌面端可以配置部分模型供应商的 API key，但该凭证不能替代移动端的 Cursor 身份。
- Claude Code 的手机与 Remote Control 能力通过 Claude 账号及符合条件的订阅计划提供。终端中的 API key 可以决定本地调用和计费，但不能替代 Claude App 的账号和远控资格。

因此，问题并不是“手机是否应该保存模型 API key”。生产级设计恰恰不应该把 Router key 复制到手机。问题在于：**官方控制身份与模型执行身份通常属于同一个产品体系，缺少一个独立、可自托管、能复用本机凭证的控制层。**

### 1.3 团队 Router 场景放大了这一问题

许多团队通过统一网关管理模型访问，原因包括预算、审计、模型路由、区域可用性和供应商切换。开发者电脑上可能只有公司下发的 Router 地址与 API key，并没有对应厂商的个人付费账号。

这些团队需要的不是另一套模型订阅，而是：

- 不改变既有模型网关和计费路径。
- 不把 Router key 上传到手机或新的 SaaS。
- 为每个控制设备建立独立身份、撤销和审计能力。
- 用统一界面管理不同 Agent，而不是为每个 Agent 安装一套远控产品。

## 2. 产品定义

### 2.1 一句话定位

> **在手机上安全查看和控制工作站中的 Codex、Cursor 与 Claude Code，同时保留本机配置、模型路由和执行权限边界。**

### 2.2 目标用户

首要用户是满足以下一个或多个条件的程序员：

- 编码 Agent 会运行较长时间，需要离开电脑后继续关注。
- 同时使用 Codex、Cursor、Claude Code 中的两种或更多工具。
- 使用 OpenRouter、LiteLLM、企业模型网关或其他 BYOK 配置。
- 代码、依赖、VPN、证书或内部工具只能留在本机环境。
- 希望远程操作 Agent，但不愿开放完整远程桌面或 Shell。

项目首先服务个人开发者和小型技术团队。企业级多租户、复杂 RBAC、合规报表和云端 Agent 调度不是当前开源版本的成立前提。

### 2.3 核心承诺

1. **模型凭证不因手机控制而迁移**：手机不需要知道 Router API key，控制面也不应托管模型凭证。
2. **工作站保留最终执行权**：手机发送的是用户意图；Workstation Companion 验证身份、能力和当前状态后决定是否执行。
3. **一个工作台管理多个 Agent**：不同 runtime 被归一为任务、消息、进度、产物、审批和控制能力。
4. **控制范围小于远程终端**：优先暴露结构化、可审计的 Agent 动作，而不是任意 Shell。
5. **能力不足时明确降级**：适配器只能报告真实能力；无法安全取得控制权时保持只读或拒绝操作。

### 2.4 非目标

- 不提供新的基础模型或推理服务。
- 不共享、转售或绕过任何厂商的个人订阅额度。
- 不承诺通过任意兼容接口复刻官方私有功能。
- 不把完整远程桌面、通用 SSH 或任意命令执行作为手机端默认能力。
- 不在多个客户端之间抢占同一会话的写入权。
- 不把开发阶段的 Quick Tunnel 描述为生产级安全连接。

## 3. 项目特点与核心优势

### 3.1 控制身份与模型凭证解耦

项目将传统上混在一起的四类身份拆开：

```text
控制设备身份       手机是否有权连接这台工作站
工作站用户身份     Companion 能访问哪些本地项目和进程
Agent 会话身份      当前任务属于 Codex、Cursor 或 Claude Code 的哪个会话
模型调用凭证       Agent 使用官方账号、API key 还是企业 Router
```

模型凭证只由本地 Agent 读取。移动端通过设备配对获得有限控制能力，而不是通过复制模型密钥获得权限。这使 Router、BYOK 和官方订阅都可以作为工作站侧的实现细节。

### 3.2 厂商中立，而不是最低公分母

统一界面不意味着假装所有 Agent 完全相同。共享协议描述通用任务语义，每个适配器同时声明真实能力：消息、停止、审批、结构化工具调用、diff、测试、历史记录、快照和新建任务等。

移动端只展示当前任务实际支持的操作。这种 capability-gated 设计比用终端文本猜测状态更可靠，也允许项目逐步采用各 Agent 的公开 API、SDK 或结构化事件流。

### 3.3 Local-first 数据与执行边界

工作站是项目文件、任务状态和执行策略的权威来源。命令在工作站执行，Agent 使用工作站已有的仓库、依赖、VPN、MCP、登录态和模型配置。

生产目标中的云服务只负责设备发现、连接协商、通知和加密信封路由，不应成为代码仓库、模型密钥或任务执行权限的所有者。需要注意，local-first 不代表发送给模型供应商的必要上下文也留在本地；该数据边界仍由用户选择的 Agent 和模型供应商决定。

### 3.4 面向 Agent 的结构化控制

与远程桌面相比，项目传输的是任务事件和有范围的命令，而不是连续屏幕画面。与 SSH 相比，手机端默认不能执行任意 Shell。由此获得：

- 更适合小屏幕的任务时间线和审批体验。
- 更窄的远程权限范围。
- 可表达的命令目标、有效期、nonce 和幂等语义。
- 对断线重连、离线通知和事件回放更自然的支持。
- 为后续审计与团队策略保留结构化基础。

### 3.5 尊重本地会话所有权

同时从桌面和手机写入同一 Agent 会话可能造成状态损坏、重复执行或审批错配。当前实现会识别外部 writer：

- Companion 没有控制权时，会话保持只读。
- 只有 Companion 自己启动和监管的 turn 才能获得相应停止或审批能力。
- 不确定当前 owner 或无法连接原 owner 时，适配器失败关闭，而不是偷偷复制或分叉会话。

### 3.6 开源与可检查性

远程控制开发工作站天然涉及高权限边界。开源让用户能够检查 Companion 读取了哪些本地数据、命令如何被验证、适配器是否访问凭证，以及中继究竟能看到什么。

对本项目而言，开源也有直接的工程价值：Agent 客户端更新频繁，公开的兼容性测试、社区适配器和版本报告比封闭团队独自追赶更可持续。

## 4. 当前实现

### 4.1 已实现的垂直切片

| 模块 | 当前能力 |
|---|---|
| Mobile PWA | 项目与任务导航、完整时间线、状态、消息、停止、审批、产物和设备状态 |
| Workstation Companion | Agent 发现、事件归一、控制权判断、本地策略边界和命令执行 |
| Shared protocol | 任务状态、控制状态、能力、历史、审批、产物、事件序列和命令契约 |
| Development relay | WebSocket 事件传输、重连、设备路由和开发配对 token |
| Codex adapter | 会话发现、历史、继续任务、实时事件、diff、停止及命令/文件审批 |
| Cursor adapter | 工作区与会话发现、历史、状态、Desktop Bridge 消息及本地 relay fallback |
| Claude Code adapter | JSONL 历史、同会话 CLI resume、实时刷新、新任务和受监管进程停止 |
| macOS packaging | 自包含应用及 PKG 构建，可打包 Node.js、前端、cloudflared 和本地辅助组件 |

### 4.2 三类 Agent 的适配原则

#### Codex

优先使用结构化 app-server 协议。对其他客户端持有 writer lock 的会话保持只读；当 Companion 获得会话控制权后，转发实时输出、工具活动、diff、停止与明确的审批请求。

#### Cursor

以只读方式读取本地会话索引和历史，不读取密钥记录。消息优先通过同用户的 Desktop Bridge 发送；不可用时使用本地扩展和 macOS 辅助功能完成有限的同会话输入，并在本地存储出现对应用户消息后才确认成功。

该 fallback 依赖 Cursor 桌面进程、解锁的 macOS 会话和一次性辅助功能授权，属于兼容路径，不应被当作稳定的公共 API。

#### Claude Code

以项目 transcript JSONL 作为发现和历史来源，不读取 Claude 凭证或设置文件。继续任务时直接调用已安装 CLI 的 `--resume`，因此自然复用本地已有的官方账号、API key 或 Router 配置。只有 Companion 启动的子进程可以被手机停止；外部终端正在写入的会话保持只读。

### 4.3 当前开发模式的限制

`./run.sh` 使用 Cloudflare Quick Tunnel 暴露临时 HTTPS/WSS 地址，并通过 URL 中的随机 token 提供额外保护。这适合真实手机验证，但仍有以下限制：

- token 是开发期门槛，不是完整设备身份。
- 尚未实现设备公钥、签名命令与端到端加密信封。
- Quick Tunnel 域名会变化，也没有可用性承诺。
- 获得完整 URL 的人可能访问端点。

因此，当前远程 QR 模式不应用于敏感仓库或不可信网络。生产安全要求以 [安全模型](security.md) 为准。

## 5. 与替代方案的区别

| 方案 | 优点 | 对本项目目标的缺口 |
|---|---|---|
| 厂商官方手机端 | 集成深、体验一致、无需自建协议 | 通常依赖同厂商账号、Workspace、计划和产品边界；难以统一多 Agent |
| 手机 SSH / Mosh | 通用、成熟、可控制任何 CLI | 权限过宽；Agent 状态、diff 和审批需要从终端文本人工理解 |
| 远程桌面 | 可以操作所有桌面应用 | 小屏体验差、带宽高、缺少结构化任务和最小权限模型 |
| 云端编码 Agent | 电脑关机也能运行，易于并发 | 私有环境复现成本高；可能需要上传代码、重建依赖和迁移凭证 |
| AI Workstation Remote | 复用本机环境与凭证，统一多 Agent，结构化最小控制 | 依赖工作站在线；适配器需要持续跟进上游变化；生产安全层仍在建设 |

本项目不需要击败官方客户端的单一生态体验。它服务的是官方产品交集之外的用户：多 Agent、本地私有环境、自定义 Router，以及希望自己掌握控制通道的人。

## 6. 参考架构

```text
                         手机 PWA / 未来原生客户端
                      任务、审批、纠正、停止、新建
                                   |
                         设备签名 + 加密信封
                                   |
                  +----------------+----------------+
                  | 直连（可用时） / 最小化中继服务 |
                  +----------------+----------------+
                                   |
                    Workstation Companion 策略边界
                  身份验证 / 能力检查 / 幂等 / 审计
                                   |
             +---------------------+---------------------+
             |                     |                     |
        Codex adapter         Cursor adapter      Claude adapter
             |                     |                     |
        本地 Agent 会话、项目、工具、登录态和 Router API key
```

核心原则是：中继可以传递数据，但不能授予 Companion 未允许的能力；手机命令已经通过身份验证，也不代表它可以绕过本地策略。

## 7. 安全与隐私原则

生产版本必须满足以下底线：

1. QR 只承载一次性挑战或短期引导信息，不承载长期 bearer 权限。
2. 每台手机和工作站生成独立设备密钥，并存放于 Secure Enclave 或 Keychain 等系统安全存储。
3. 事件与命令使用端到端加密；中继只处理必要路由元数据。
4. 命令绑定设备、工作站、项目、Agent、任务、动作、过期时间和 nonce。
5. 所有命令具备重放保护与幂等处理，手机只有在收到工作站确认事件后才显示成功。
6. 查看、消息、审批、停止、快照、终端和桌面能力彼此分离。
7. 审批默认只生效一次，不静默扩大为永久授权。
8. 手机和工作站都能立即撤销设备，并保留可检查的本地记录。
9. 模型 API key、Router key、Agent token 和本地凭证不通过控制通道传到手机。
10. 未知请求、无法匹配的审批和失去 owner 的会话默认拒绝或只读。

完整威胁边界和当前开发限制见 [安全模型](security.md)。

## 8. 开源产品路线

### 阶段 A：可信的个人版本

- 持久事件账本、单调序列、游标回放和跨重启恢复。
- 安装级工作站身份与多手机设备身份。
- QR 挑战、设备密钥、签名命令和端到端加密信封。
- 设备列表、撤销、连接状态和本地审计记录。
- 明确区分本地直连、中继连接和开发 Quick Tunnel。
- 针对三类 Agent 的版本探测、健康检查和兼容性测试。

这是下一个版本的发布门槛。

### 阶段 B：可持续的开源兼容层

- 稳定 adapter SDK 与 capability contract。
- 上游版本兼容矩阵和自动回归样本。
- 在公开接口可用时替换私有数据库或辅助功能路径。
- Linux Companion/Runner 可行性验证。
- 自托管 relay 的标准部署方式。
- 通知、深链接和更可靠的后台恢复。

### 阶段 C：可选的团队协作能力

只有个人版本稳定并出现真实协作需求后，再考虑：

- 工作站共享与成员级授权。
- 每人独立设备身份，而不是共享团队 Router key 作为身份。
- 项目级角色、双人审批和审计导出。
- 团队自托管控制面。
- Slack、GitHub 或内部开发门户入口。

团队能力是开源项目的自然延伸，但不应阻塞个人开发者版本。`product-strategy.md` 中的 CI Repair Desk 是一条可能的未来商业化探索，不代表当前开源项目的产品承诺。

## 9. 开源项目的护城河

本项目的长期价值不来自一个手机聊天框，而来自以下可以持续积累的工程资产：

- 对不同 Agent 生命周期、控制权和审批语义的统一抽象。
- 经真实版本验证的 Codex、Cursor、Claude Code 适配器。
- 上游接口变化时可复现的兼容性测试和降级策略。
- 不读取模型密钥、失败关闭、一次性审批等安全默认值。
- 适合移动端的结构化任务、diff、测试和工具时间线。
- 本地、直连、中继和未来自托管环境之间一致的协议。

官方厂商会继续完善各自的移动端，但很难优先服务竞争对手的 Agent 和任意 Router。通用远程工具则很难理解 Agent 的会话所有权、审批和结构化产物。项目应长期守住这两类产品之间的交叉位置。

## 10. 成功标准

开源项目近期不应以注册用户或模型 token 消耗量衡量。更有意义的指标是：

- 从安装到手机看到首个真实任务的中位时间。
- 远程消息、停止和审批的确认成功率。
- 断线重连后任务状态恢复正确率。
- 支持版本范围内三类 Agent 的兼容测试通过率。
- 因控制权不明确而正确进入只读状态的比例和原因。
- 安全相关未授权执行、重复执行和凭证泄露事件数，目标均为零。
- 有效 issue、外部贡献者数量和 adapter 版本修复周期。

## 11. 项目表达

推荐使用以下对外描述：

> **AI Workstation Remote 是一个开源、本地优先的 AI 编程 Agent 移动控制层。它让开发者在手机上查看和控制 Mac 中的 Codex、Cursor 与 Claude Code，同时继续使用本机项目、工具、官方登录或自定义模型 Router。模型密钥留在工作站，手机只获得明确授权的任务能力。**

更短的标语：

> **Control your coding agents, not your whole desktop.**

中文：

> **远程控制你的编程 Agent，而不是整台电脑。**

不建议使用“绕过厂商账号”作为正式宣传语。项目不是规避服务条款或盗用订阅，而是提供独立于模型凭证的设备控制能力。更准确的关键词是：`vendor-neutral`、`local-first`、`BYOK-compatible`、`structured remote control`。

## 12. 风险与约束

### 上游兼容性

Cursor 的本地存储和辅助功能路径、Codex Desktop 的本地 IPC 都可能发生变化。公开接口应始终优先；非公开兼容层必须标注实验性、进行版本探测，并在不确定时退回只读。

### 工作站可用性

本地 Agent 依赖工作站开机、联网且必要的桌面会话可用。项目不会像纯云 Agent 一样在电脑关机后继续使用本地环境。

### 移动端后台限制

PWA 和移动操作系统会限制长连接及后台执行。生产实现需要把推送通知视为唤醒提示，并以 Companion 的事件账本作为状态真相。

### 安全责任

远程审批可以触发代码和命令执行，因此设备身份、签名、过期、重放保护、最小能力和撤销都不是可延后的附加功能，而是公开发布远程版本的前置条件。

### 服务条款与账号边界

项目只控制用户已合法安装和配置的本地客户端，不应提取、共享或模拟官方订阅令牌。各 Agent 和模型服务的使用仍受其自身许可、服务条款与组织策略约束。
